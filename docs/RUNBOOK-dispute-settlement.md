# Выкатка сбора за спор — раннбук

Ветка `feat/dispute-settlement`. Пять шагов, **порядок несущий**: у трёх из них
неверная очерёдность стоит денег или рассылает людям неправду.

Составлен 28 июля 2026. Броадкастов ещё не было ни одного — в
`broadcast/*/84532/` у всех трёх скриптов только `dry-run`.

Перед каждым шагом сначала **сухой прогон** без `--broadcast`. Скрипты
останавливаются на пре-флайте до траты газа, если состояние цепи не то, которое
ожидалось; обходить проверку нельзя — она и есть смысл пре-флайта.

---

## Шаг 1. Фронт и релеер

```bash
bash deploy-local.sh --all
```

**Почему первым.** Задачи 7, 7b и 7c учат интерфейс говорить правду про сбор и
про дележ. Пока они не в проде, первый же дележ разошлёт обеим сторонам
«сделка отменена, деньги возвращены клиенту» — включая того, кто получил
половину. Пуш живёт в шторке уведомлений, его не отзовёшь.

Дележ станет возможен только после Шага 4, так что формально запас есть. Но
делать этот шаг последним — значит держать заряженной ложь, которая выстрелит
через четыре дня после первого спора.

## Шаг 2. Фасет арбитров — `Replace 44 + Add 3`

```bash
forge script script/UpgradeArbiterRegistryDisputeFee.s.sol \
  --rpc-url https://sepolia.base.org --private-key $PRIVATE_KEY --broadcast -vvv
```

Монтирует `creditDisputeFee`, `withdrawTreasurySlice`, `getTreasurySlice`.

**Почему до Шага 4.** Без этого фасета зачисление сбора не проходит. Деньги при
этом **не теряются** — перевод стоит внутри `try`, весь котёл достаётся
победителю, — но протокол не берёт свои 3%, и арбитры не получают награды за
все споры этого окна. Задним числом не начислить.

Скрипт Шага 4 сам откажется стартовать при `--broadcast`, если этот шаг не
сделан. Порядок гарантирован кодом, а не памятью.

## Шаг 3. Сабграф

```bash
cd subgraph && npm run deploy:studio    # метка v2.1.0
```

**Почему до Шага 4, а не после.** Учит сабграф видеть `DisputeSplitNoVerdict`.
Выкатить его раньше реализации совершенно безопасно — он просто слушает событие,
которого пока не бывает. Выкатить позже — значит оставить окно, в котором
сделка, закрытая дележом, финализирована и пуста на цепи, а во всех интерфейсах
висит в статусе «спор». Это расхождение не заживает само.

## Шаг 4. Реализация `Agreement` — сбор и дележ

```bash
forge script script/UpgradeAgreementDisputeFee.s.sol \
  --rpc-url https://sepolia.base.org --private-key $PRIVATE_KEY --broadcast -vvv
```

Разворачивает новую реализацию, новый `AgreementDeployer` и подставляет его в
фабрику. **С этого момента новые сделки живут по новым правилам.**

**Уже созданные сделки не затронуты и не будут.** Клоны EIP-1167 намертво несут
адрес прежней реализации в своих 45 байтах; перевести существующий клон на
другую реализацию нельзя ничем. Это не миграция, а переключение того, из чего
чеканятся будущие сделки.

После броадкаста подтвердить **с цепи**, а не по логу симуляции:

```bash
cast call $DIAMOND_ADDRESS "getAgreementDeployer()(address)" \
  --rpc-url https://sepolia.base.org
```

## Шаг 5. Фабрика — гейт `ZeroFee`

```bash
forge script script/UpgradeFactoryFacetDisputeGate.s.sol \
  --rpc-url https://sepolia.base.org --private-key $PRIVATE_KEY --broadcast -vvv
```

Чистый `Replace` 13 селекторов. **Независим от Шагов 2-4** и может идти когда
угодно — гейт про комиссию платформы при создании сделки, со сбором за спор не
связан ничем.

Везёт заодно переименование ошибки из второй волны аудита
(`ZeroAddress` → `FactoryZeroAddress`, 13 revert-сайтов, смена селектора
ошибки). Релеер оба селектора уже знает и ждёт именно этого ката.

Скрипт печатает комиссии всех семи регионов, прочитанные с цепи. Ноль означает,
что регион **перестанет создавать сделки** через прямые пути фабрики, вместо
того чтобы создавать их бесплатно. На 28 июля все семь ненулевые
(2/4/7/10/4/10/7 USDC). Если увидишь ноль — лечится `setRegionFee`, а не отказом
от апгрейда.

## Откат

**У каждого скрипта своя инструкция, и она печатается им же после успеха.**
Читай её из вывода, а не отсюда: там подставлены живые адреса.

Три вещи, которые стоит знать заранее.

**Откат Шага 2 — три шага, и порядок в нём уничтожает сам себя, если перепутать.**
Второй шаг сливает накопленную долю казны через `withdrawTreasurySlice()`, а
третий делает эту функцию недостижимой. Слить надо **до** ката, иначе накопленное
станет USDC на диамонде, до которого не дотягивается ни одна смонтированная
функция, — а функции спасения в диамонде нет вообще.

**Откат Шага 4 неполон по конструкции.** Клоны, отчеканенные между выкаткой и
откатом, остаются на новой реализации навсегда и продолжают брать сбор, пока
смонтирован фасет Шага 2. Ничего не ломается: замена деплойера возвращает старое
поведение только **новым** сделкам.

**Никогда не откатывай `Replace`-ом селекторы, которых у целевого фасета нет.**
`DiamondProxy.replaceFunctions` сверяет только, что фасет другой, но **не** что
у него есть код под селектор. Такой кат **пройдёт успешно**, вызовы начнут
падать, а обзор фасетов будет показывать их смонтированными — то есть
мониторинг ничего не заметит. Для снятия селектора есть `Remove`.

## Что остаётся открытым после выкатки

Не блокеры, но знать до, а не после — `docs/OPEN-ITEMS.md`:

- **пп. 9-11** — дележ можно сбить, если договориться с арбитром: он клеймит спор
  внутри окна и молчит, либо отпускает клейм на исходе. Бесплатные обходы закрыты
  (Задачи 4 и 4b), платный остался. Плюс побочный эффект гейта 4b: бонд
  неявившегося арбитра отпирается только владельцем. Всё это — на брейншторм по
  экономике арбитров, потому что лечится жизненным циклом клейма, а не гейтами;
- **п. 12** — копирайт врёт про четыре константы контракта в 15 локалях. Худшее:
  исполнителю обещают три дня на активацию против двух в контракте, и на вторые
  сутки на той же странице у клиента уже появляется кнопка возврата;
- **п. 14** — селектор `ZeroFee` не разбирается оффчейн, поэтому отказ по нулевой
  комиссии региона выглядит безымянным ревертом;
- **п. 2** — ступени 2 и 3 лестницы казны живыми деньгами так и не проверены.
