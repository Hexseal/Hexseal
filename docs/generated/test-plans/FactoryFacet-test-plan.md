# Тест-план: FactoryFacet — Фабрика сделок и конфигурация

> Сеть: Base Sepolia · Diamond: `0xF00CC71878c226E0b64253Fb71dD802aF12165D0` · USDC: `0x036CbD53842c5426634e7929541eC2318f3dCF7e`
> Тестер: — · Дата: —

FactoryFacet деплоит Agreement-контракты и хранит конфигурацию протокола (комиссия, форвардер). Большинство действий — через `/admin` (только владелец Diamond) или неявно — через принятие заявки на Job Board.

---

## Сценарий 1: Создание сделки через принятие заявки (Job Board)

**Роль:** Клиент
**Страница:** `/job/[id]`
**Предусловие:** клиент нажал «Hire» на исполнителя (см. JobBoard тест-план сценарий 3)

> Factory деплоит Agreement **автоматически**, пользователь не вызывает FactoryFacet напрямую.

- [ ] После нажатия «Confirm Hire» в модалке — транзакция проходит
- [ ] Тост: «Executor accepted! Agreement deployed & funded.»
- [ ] Автоматический редирект на `/deal/[address]`

**Проверить:**
- [ ] Адрес сделки валидный — можно открыть на basescan
- [ ] На странице сделки видны: Клиент, Исполнитель, сумма, дедлайн
- [ ] Статус `CREATED` (ждёт фондирования)
- [ ] В реестре Diamond: `hasActivePair(client, executor)` = true (проверить через cast call или explorer)

---

## Сценарий 2: Владелец меняет адрес получателя комиссий (feeRecipient)

**Роль:** Владелец Diamond (owner)
**Страница:** `/admin`
**Предусловие:** подключён owner-кошелёк

- [ ] Открыть `/admin`
- [ ] Найти поле **«Fee Recipient»**
- [ ] Ввести новый адрес кошелька
- [ ] Нажать **«Update»** → MetaMask запрашивает транзакцию (owner платит газ напрямую)
- [ ] Подтвердить → тост об успехе

**Проверить:**
- [ ] После следующей завершённой сделки — комиссия ушла на новый адрес, а не старый
- [ ] Попытка от чужого кошелёк → revert (OnlyOwner)

---

## Сценарий 3: Владелец меняет TrustedForwarder

**Роль:** Владелец Diamond
**Страница:** `/admin`
**Предусловие:** задеплоен новый MinimalForwarder

- [ ] В поле **«Trusted Forwarder»** ввести адрес нового форвардера
- [ ] Нажать **«Update»** → подтвердить транзакцию
- [ ] После этого gasless-транзакции идут через новый форвардер

**Проверить:**
- [ ] Старый форвардер больше не принимается как валидный
- [ ] Новый gasless-вызов (например, Apply for Job) проходит через новый форвардер

---

## Граничные случаи

- [ ] **Деплой сделки с нулевой суммой** — должен быть revert ещё на этапе Job Board (ZeroAmount), до вызова Factory
- [ ] **Деплой двух сделок между одной и той же парой** — `hasActivePair(client, executor)` = true → acceptApplicant reverts (защита от дублей)
- [ ] **feeRecipient = нулевой адрес** → ввести `0x000…` → должен быть revert или валидация в UI
- [ ] **trustedForwarder = нулевой адрес** → аналогично
