# Тест-план: MinimalForwarder — Gasless-транзакции (ERC-2771)

> Сеть: Base Sepolia · Forwarder: `0x41c66b80B1445F48AF3863763BC0EC0549413CD7` · Diamond: `0xF00CC71878c226E0b64253Fb71dD802aF12165D0`
> Тестер: — · Дата: —

MinimalForwarder позволяет пользователям делать транзакции **без ETH** — они подписывают запрос, релеер платит газ. Тестируем что gasless-путь работает для всех ключевых действий. Отдельный ETH у тестового кошелька **не нужен**.

---

## Сценарий 1: Gasless-действия работают без ETH на кошельке

**Предусловие:** тестовый кошелёк с USDC, но **без ETH**

Пройти весь стандартный флоу, убедиться что каждое действие проходит gasless:

- [ ] **Apply for Job** — Исполнитель откликается на заказ → только подпись кошелька, никаких ETH
- [ ] **Activate** — Исполнитель активирует сделку → только подпись
- [ ] **Mark Done** — Исполнитель сигнализирует о завершении → только подпись
- [ ] **Release Funds** — Клиент релизит → только подпись (USDC permit + gasless)
- [ ] **Raise Dispute** — Клиент поднимает спор → только подпись
- [ ] **Claim Case** (арбитр) — commit-reveal через релеер

**Проверить для каждого:**
- [ ] Транзакция прошла и видна на basescan
- [ ] `msg.sender` внутри контракта = адрес пользователя (не релеера) — проверить через события
- [ ] Газ оплатил **релеер** (`0x...relayer`), а не пользователь — видно в «From» транзакции на basescan

## Сценарий 2: Replay-атака — один запрос нельзя выполнить дважды

**Инструмент:** скрипт или Foundry test
**Цель:** убедиться что nonce-защита работает

- [ ] Сохранить подписанный ForwardRequest (например, для Apply for Job)
- [ ] Выполнить его первый раз → успешно
- [ ] Попробовать выполнить тот же request второй раз → revert (nonce уже использован)

---

## Сценарий 3: Невалидная подпись не проходит

- [ ] Передать ForwardRequest с подписью от другого кошелька (не from)
- [ ] `execute()` должен вернуть `success = false` или revert

---

## Сценарий 4: Истёкший request не проходит

- [ ] ForwardRequest с `deadline` в прошлом → revert `RequestExpired` или аналог
- [ ] ForwardRequest с `deadline` в будущем → проходит

---

## Сценарий 5: Правильный форвардер указан в Diamond

**Инструмент:** cast call или basescan

- [ ] `cast call $DIAMOND "getTrustedForwarder()(address)" --rpc-url $BASE_SEPOLIA_RPC_URL`
- [ ] Результат = `0x41c66b80B1445F48AF3863763BC0EC0549413CD7`
- [ ] `cast call $AGREEMENT "isTrustedForwarder(address)(bool)" $FORWARDER --rpc-url ...` = `true`

---

## Граничные случаи

- [ ] **Слишком маленький gasLimit в ForwardRequest** → транзакция reverts внутри, но execute сам по себе проходит (out-of-gas в sub-call)
- [ ] **target = нулевой адрес** → revert или пустой success
- [ ] **Вызов execute от неизвестного релеера** — execute публичный, любой может вызвать. Безопасность — в подписи (проверить что подмена релеера не помогает)
