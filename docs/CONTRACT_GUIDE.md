# Hexseal — Что умеют смарт-контракты

> Простое описание всех функций. Без технического жаргона.
> Актуально на: июнь 2026

---

## Как это устроено в целом

Hexseal — это фриланс-биржа на блокчейне. Вместо сервера всё живёт в смарт-контрактах.
Один главный контракт (Diamond) управляет всем остальным.

**Действующие лица:**
- **Клиент** — тот, кто платит за работу
- **Исполнитель** — тот, кто делает работу
- **Арбитр** — независимый судья при спорах (назначается владельцем платформы)
- **Владелец (Owner)** — тот, кто развернул Diamond (управляет настройками)

---

## Diamond — главный контракт

Адрес: `0x7A91d700CF2a201E99F0aD3C3b4f4D79CFE69557`

Это не один большой контракт — внутри Diamond "живут" несколько модулей (фасетов).
Каждый отвечает за свою область.

## 1. Создание сделок (FactoryFacet)

| Что делает | Кто может | Детали |
|---|---|---|
| Создать новую сделку | Любой | Клиент и исполнитель договорились — создаётся отдельный эскроу-контракт |
| Поменять адрес кошелька для комиссий | Только владелец | Куда уходит % платформы |
| Поменять адрес форвардера | Только владелец | Технический: для безгазовых транзакций |
| Поставить платформу на паузу | Только владелец | Экстренная остановка создания новых сделок |

## 3. Сделка (Agreement.sol)

Каждая сделка — это отдельный контракт. Деньги (USDC) лежат в нём.

### Жизненный цикл сделки

```
СОЗДАНА → АКТИВИРОВАНА → РАБОТА ВЫПОЛНЕНА → ЗАКРЫТА
                                         ↘ СПОР → РЕШЁН АРБИТРОМ
```

| Шаг | Статус | Что происходит |
|---|---|---|
| Создание | PENDING (0) | Контракт создан, деньги ещё не отправлены |
| Клиент оплатил | FUNDED (1) | USDC заморожен в контракте |
| Исполнитель принял | ACTIVE (2) | Работа началась |
| Исполнитель сдал | DONE (3) | Ждём подтверждения клиента |
| Клиент доволен | COMPLETED (5) | Деньги ушли исполнителю |
| Спор | DISPUTED (4) | Кто-то не согласен с результатом |
| Арбитр решил в пользу исполнителя | RESOLVED (6) | Деньги ушли исполнителю |
| Арбитр решил в пользу клиента | REFUNDED (7) | Деньги вернулись клиенту |

### Функции сделки

| Функция | Кто вызывает | Что происходит |
|---|---|---|
| `fund()` | Клиент | Переводит USDC в эскроу. Сделка "оплачена" |
| `activate()` | Исполнитель | Принимает работу, дедлайн начинается |
| `markDone()` | Исполнитель | Говорит "я сделал, проверяй" |
| `release()` | Клиент | Подтверждает работу, деньги идут исполнителю |
| `raiseDispute()` | Клиент или исполнитель | Открывает спор — нужен арбитр |
| `triggerAutoApprove()` | Любой | Если клиент не реагировал N дней — деньги сами идут исполнителю |
| `triggerActivationTimeout()` | Любой | Если исполнитель не принял работу N дней — деньги возвращаются |
| `triggerDeadlineTimeout()` | Любой | Если дедлайн прошёл и ничего не сдано — деньги возвращаются |
| `triggerArbiterTimeout()` | Любой | Если арбитр молчал N дней — деньги возвращаются клиенту |

> Безгазовые: клиент/исполнитель могут всё делать без ETH — газ оплачивает платформа

## 4. Арбитраж (ArbiterRegistryFacet)

Когда стороны не договорились — спор решает арбитр.

### Кто такой арбитр

Арбитр — это доверенный судья, назначенный владельцем платформы (или выбранный через DAO когда наберётся 100 000 активных пользователей).

### Процесс разрешения спора

```
1. Арбитр резервирует спор (commit-reveal, анти-фронтран)
2. Арбитр изучает ситуацию, подаёт вердикт
3. Вердикт исполняется — деньги идут победителю
```

| Функция | Кто | Что |
|---|---|---|
| `commitDisputeClaim()` | Арбитр | Шаг 1: резервирует спор скрытым хешем |
| `claimDispute()` | Арбитр | Шаг 2: раскрывает — теперь этот спор его |
| `releaseDisputeClaim()` | Арбитр или владелец | Отказывается от спора (возвращает в очередь) |
| `submitVerdict()` | Арбитр | Подаёт решение: "клиент прав" или "исполнитель прав" |
| `finalizeVerdict()` | Любой | Исполняет решение — деньги идут победителю |
| `overturnVerdict()` | Владелец или DAO | Отменяет решение арбитра, арбитр теряет XP |
| `freezeVerdict()` | Владелец или DAO | Временно блокирует исполнение (расследование) |
| `unfreezeVerdict()` | Владелец или DAO | Снимает блокировку |

### Управление арбитрами

| Функция | Кто |
|---|---|
| `addArbiter()` | Владелец или главный арбитр |
| `removeArbiter()` | Владелец или главный арбитр |
| `setChiefArbiter()` | Только владелец |
| `applyAsArbiter()` | Любой с XP ≥ 3000 (только в DAO-режиме) |

### Вознаграждение арбитров

| Функция | Кто |
|---|---|
| `fundVault()` | Владелец — пополняет кошелёк платформы для выплат |
| `setRewardPerDispute()` | Владелец — устанавливает сколько USDC за спор |
| `withdrawArbiterReward()` | Арбитр — забирает заработанное |

### Экстренная очистка

| Функция | Описание |
|---|---|
| `clearStuckVerdict()` | Ручная резервная очистка зависшего вердикта (только владелец) |

> Авто-очистка работает сама: если сделка закрылась через таймаут пока вердикт ждал исполнения — система сама чистит запись автоматически.

## 5. Репутация и XP (ReputationFacet)

Каждый участник копит очки опыта (XP) за успешные сделки.

| Действие | XP |
|---|---|
| Успешно закрыл сделку | +50 XP (обеим сторонам) |
| Сделка с новым человеком | +100 XP |
| Арбитр решил честно | +30 XP арбитру |
| Вердикт отменён владельцем | -200 XP арбитру |

**XP нужен для:** доступа к DAO и регистрации как арбитр (нужно 3000+ XP).

---

## 6. Доска заказов (JobBoardFacet)

Клиент публикует задание — исполнители могут откликнуться.

| Функция | Кто |
|---|---|
| `postJob()` | Клиент — создаёт заказ с описанием и бюджетом |
| `editJob()` | Клиент — редактирует заказ |
| `deleteJob()` | Клиент — удаляет заказ |
| `getJob()` | Любой — читает детали заказа |

---

## 7. Доска услуг (ServiceBoardFacet)

Исполнитель публикует свою услугу — клиенты могут её купить.

| Функция | Кто |
|---|---|
| `postService()` | Исполнитель — создаёт оффер с описанием и ценой |
| `editService()` | Исполнитель — редактирует |
| `deleteService()` | Исполнитель — удаляет |
| `getService()` | Любой — читает детали |

---

## 8. NFT-значки (JobNFTFacet, OfferNFTFacet)

**JobNFT** — Soulbound (непередаваемый) NFT, выдаётся автоматически когда сделка успешно закрыта. Хранится у исполнителя как подтверждение выполненной работы.

**OfferNFT** — NFT-оферта. Исполнитель может минтить NFT-предложения своих услуг.

| Функция | Что |
|---|---|
| `mintJobNFT()` | Выдать значок за выполненную работу (вызывается Agreement автоматически) |
| `mintOfferNFT()` | Создать NFT-оффер своей услуги |
| `getJobNFT()` | Посмотреть NFT по адресу сделки |
